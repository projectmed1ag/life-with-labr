# Life with Labr — VPS

Сайт и админка работают одним Node.js 24 приложением за Nginx.

- Сайт: https://lifewithlabr.ru
- Админка: https://admin.lifewithlabr.ru
- Код: `/opt/lifewithlabr/current` — ссылка на каталог релиза.
- Node: `/opt/lifewithlabr/runtime/bin/node`.
- Постоянные данные: `/var/lib/lifewithlabr/content.sqlite`, фотографии: `/var/lib/lifewithlabr/uploads`.
- Сервис: `lifewithlabr.service`, слушает только `127.0.0.1:4180`, пользователь `lifewithlabr`.
- Пароль хранится как scrypt-хеш в SQLite. Начальная учётная запись создаётся `cms/init-admin.mjs` через stdin. Паролей в коде и Git нет.
- Настройки доменов: отдельный `/etc/nginx/conf.d/lifewithlabr.conf`.
- Сертификат: `/etc/letsencrypt/live/lifewithlabr.ru`, автоматическое продление Certbot с reload Nginx.

## Публикация

«Сохранить черновик» сохраняет работу, не меняя опубликованную версию. «Опубликовать» сначала проверяет и строит страницы, затем сохраняет новую версию и атомарно заменяет страницы в памяти. Новые помёты получают постоянные адреса `/puppies/litter-…/` без отдельного развёртывания кода.

Галерея: название, дата, текст, до 20 фото; порядок фото меняется кнопкой «Раньше». Первое фото — обложка. Помёт: название, дата рождения, описание, мама и папа (можно взять из другого помёта), щенки с полом, окрасом, описанием, фото, ценой и статусом. Оставленное пустым поле цены ничего не показывает. Статусы: не указан, свободен, забронирован, уехал в новую семью. Для брони и новой семьи кнопка уточнения наличия скрыта; цена, если задана, остаётся справа от клички.

«Снять с публикации» оставляет черновик. «В архив» скрывает запись с сайта, не удаляя её данные и фотографии. Из архива можно восстановить черновик и опубликовать снова. При конфликте двух вкладок сохранение отклоняется вместо перезаписи чужих изменений.

Русский и английский интерфейс сайта сохранены. Собственные тексты, введённые в админке, публикуются на языке ввода; автоматического перевода новых текстов нет.

## Обновление и перенос

1. Собрать новый отдельный каталог релиза, установить зависимости по `pnpm-lock.yaml` (`pnpm install --frozen-lockfile --prod`), пройти проверки.
2. Сохранить резервную копию. Переключить ссылку `current`, перезапустить `lifewithlabr.service`, проверить `/healthz`, публичные страницы и вход. Для отката вернуть предыдущую ссылку; данные не трогать.
3. Ежедневно `lifewithlabr-backup.timer` создаёт архив SQLite-снимка и всех загрузок в `/var/backups/lifewithlabr`, хранит 14 дней. Файлы закрыты от доступа через сайт. Это копия на том же VPS; для защиты от потери всего сервера её нужно отдельно скачивать.
4. Для переезда: перенести код, runtime и последний архив; восстановить SQLite-снимок как `content.sqlite`, каталог `uploads`, владельца `lifewithlabr` и права 700/600. Сессии можно очистить. Запустить, проверить, затем переключить DNS и выпустить сертификат на новом сервере.

При восстановлении не подменять открытую SQLite-базу: сначала остановить сервис. В комплект начального развёртывания входят только исходные данные `src/data/*.json`, а не локальная тестовая база.
